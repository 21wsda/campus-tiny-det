# TinyPerson：远端小目标的补充验证

> 丙 9/27 起草。用途：技术方案里「为什么还要在 TinyPerson 上再验一遍」的一段叙事。
> 规则：只写校园远端，不写无人机。等甲把 TinyPerson 上的完整方法训完，第三段末尾补上相对变化。
> 数据与配置：`configs/tinyperson.yaml`，标签抽查见 `docs/figures/tinyperson_check/`。

教室数据能覆盖「中近距的小目标」，但校园里还有更难的一类场景：操场、校门口、长廊尽头。人和镜头隔着几十米，在 1080p 画面里只有十几个像素高，比教室后排的头还小得多。这类目标不是框得飘，而是常常整块消失在特征图上。

为了确认我们的改法不是只对教室数据有效，我们在 TinyPerson 这个公开的远景小目标基准上补了一组验证：它的特点是目标极小、极密、远景大场景，是公开数据里最极端的一档。同一套配置、同样 100 epoch、同样 imgsz=640，只换数据集。

需要说清楚边界。我们用 TinyPerson 只做极端远景下的压力测试——看的是接上 P2、再把拼接改成可学习加权融合之后，模型还能不能顶住更小的目标；本项目的落地场景始终是校园里固定的监控摄像头。也不拿它在 TinyPerson 上的绝对精度说事：这个数据集本身就极难，官方 n 的 mAP50 只有 0.127，mAP50-95 只有 0.0367，我们在同一套配置下也训了完整方法：mAP50=0.124、mAP50-95=0.0363，比官方 n 的 0.127 / 0.0367 基本持平、略低 0.003。这个结果我们照实写：TinyPerson 这类极端远景小目标，对 3M 量级的轻量模型仍然是超纲的，只改脖子带来的增益在这里并不明显；教室数据上的提升才是我们方法的主要证据。

如果将来要在真实校园远端上岗，还需要用本校的远端监控画面重新标数据、重新微调；这一步没有做，我们也不宣称做了。
